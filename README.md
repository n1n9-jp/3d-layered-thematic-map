# 3D Layered Thematic Map

**東京23区の水害（洪水・高潮）を、住民説明会や報道の解説のように、専門でない人に説明するための地図**の試作です。
標高・浸水・人口・公共交通・避難の5枚の平面レイヤーを縦に積んで、次の関係を見せます。

> 海面より低い土地に、これだけの人（うち高齢者がこれだけ）が住んでいて、想定される浸水の深さはこれだけで、水は何日も引かず、避難できる場所はここにある（あるいは、近くにはない）

静止画でよく見る「傾けて積んだ地図」を、同じ地点をレイヤー間で対応づけて読める道具にすることが目的で、中心の見せ方は[断面](#断面)です。台地から低地へ線を引くと、標高が海面より下がる位置、浸水が深くなる位置、人が多く住む位置、避難場所のある位置・ない位置が、上下に並びます。

**この地図は試作で、避難の判断に使うものではありません。実際の避難は、各区のハザードマップと避難情報に従ってください。** 画面にも、左上と右の列の下に書いています。

ブラウザで動かせることは次のとおりです。

- レイヤー間の間隔を変えて、重ね合わせた状態から積み上げた状態まで連続的に切り替える
- 視点を回転・パン・ズームして、積層を好きな角度から眺める
- 何も選んでいないとき、右の列に、23区全体の主な数字（深さ 3m 以上の浸水が想定される区域に住む人、標高 0m 未満の土地に住む人、洪水・高潮で使える避難場所の数、浸水が深いのに洪水・高潮用の指定がない区）を大きく出し、深さの区分ごとの人口の横棒の表を添える。数え方・データの注意は、折りたたんでおく
- 浸水の想定（洪水と高潮の大きいほう・洪水・高潮）と見るもの（深さ・水が引くまでの期間）、人口の見るもの（総人口・65歳以上）を、レイヤー一覧の行で切り替える。描画・凡例・探針・クローズアップ・断面が連動する
- レイヤー間の間隔を変えて、重ね合わせた状態から積み上げた状態まで連続的に切り替える
- 視点を回転・パン・ズームして、積層を好きな角度から眺める
- 地図上の1点に「探針」（全レイヤーを貫く垂直線）を立てて、その地点の各レイヤーの値（洪水・高潮の深さと継続時間、人口と65歳以上、最寄りの避難場所と病院）を読む
- 探針を固定した地点の周辺（半径 1〜5 km）を拡大した「クローズアップ」を右の列に並べて、円の中の集計（浸水の面積の割合、避難場所の数、人口、浸水が想定される区域に住む人など）を、その地点の値と見比べる。固定した印のドラッグや、クローズアップの中のクリックで、固定したまま中心の地点を動かせる
- 全体の地図で2点を結ぶ線（または、例の線のボタン）で、全レイヤーを縦に切る「断面」。線に沿って、標高・浸水の深さ（または継続時間）・人口密度の変化、鉄道との交差、近くの避難場所・病院の並びと、避難場所のデータがない区間を、地図の中に立てたグラフ（形をつかむ）と、右の列の平らなグラフ（値を正確に読む）で見比べる。2つは連動する
- レイヤーの並べ替え・表示切替・単独表示（真上からの2D表示）

## 使い方

Node.js 22 で動作を確かめています。リポジトリを取得したら、依存関係を入れます。

```sh
npm ci            # 依存関係の導入（package-lock.json のとおりに入れる）
npm run dev       # 開発サーバーの起動。表示される URL（既定は http://localhost:5173/）をブラウザで開く
npm run build     # 型検査（tsc --noEmit）と本番ビルド。出力は dist/
npm run preview   # ビルド結果の確認用サーバー
npm test          # 単体テスト（vitest）
```

- 画面が読むデータは `public/data/` にあります。作り方は[データの再生成](#データの再生成)を参照してください。道路（`roads.geojson`）と学校（`facilities.geojson` の `kind: 'school'`）は、データと前処理を残していますが、画面は読みません（積層から外しました）。
- `public/data/` にファイルがないレイヤーは、レイヤー一覧に「読み込み失敗」と出て、ほかのレイヤーは動き続けます。
- 前処理の結果によらず画面を試したいときは、仮データ（`public/data-fixture/`）に切り替えます。`http://localhost:5173/?data=fixture` を開いてください。仮データは `node scripts/make-fixtures.mjs` で作った架空の地図で、実在の地名・数値ではありません。何度実行しても同じ出力になります。

## 画面の構成

- 平行投影の3Dビューに、5枚のレイヤーを下から順に積みます。
  1. 標高（`elevation`）：海面より低い土地（0m 未満）が青
  2. 浸水（`flood`）：洪水・高潮の浸水想定（深さ、または水が引くまでの期間）
  3. 人口（`population`）：総人口、または65歳以上の人口密度
  4. 公共交通（`transit`）：避難の経路として残した、鉄道の路線と駅
  5. 避難（`shelters`）：指定緊急避難場所と病院。避難場所のデータを公開していない区は灰の網掛け、洪水・高潮用の指定が 0 件の区は、浸水の想定で、琥珀の斜線（浸水が深い）とごく薄い塗り（浸水が小さい）に書き分ける（[避難場所の指定のない区](#避難場所の指定のない区3通りの書き分け)）
  - 道路と学校は、積層から外しました（読み込みません。前処理とデータファイルは残しています）。
- 画面の部品と位置
  - 右上：パネル。視点のボタン、レイヤー間隔のスライダー、レイヤー一覧（並べ替え・表示切替・単独表示・凡例）。収まらないときは、パネルの中をスクロールします
  - 右の列：「選んだ地点の情報」。右上のパネルのすぐ左に、画面の高さいっぱいで、中身の有無にかかわらず常に同じ幅で置きます（幅は右上のパネルを除いた画面の幅の 33%、380〜560 px。1400 px の画面で 380 px、2000 px の画面で 560 px）。探針の状態で中身が変わります（[選んだ地点の情報の列](#選んだ地点の情報の列)）
    - 探針がないとき：23区全体の主な数字と表（[23区全体の集計の見せ方](#23区全体の集計の見せ方)、[集計の数え方](#集計の数え方浸水が想定される区域に住む人)）。操作の手がかり（短く）は、スクロールする集計の外の、列の下端に固定する
    - カーソルを置いただけのとき：区名と、各レイヤーの「この地点」の値
    - 固定しているとき：上にクローズアップ、下にレイヤーごとの表（「この地点」と「半径 ○ km 内」の集計を並べる）
    - 列の最上部には、「読み方」の「地点」「断面」の切り替えがあります（どのときも出ます）。「地点」は上の3通り（探針とクローズアップ）、「断面」は線を引く手がかり、または線に沿った各レイヤーのグラフです（各グラフは、全体の地図の対応する段と同じ高さに並びます。[断面](#断面)）
  - 左上：地図の題（「東京23区の水害を読む地図」）と、試作で避難の判断には使えないことの注意。右の列の下にも、「試作です。避難の判断には使えません。実際の避難は、各区のハザードマップと避難情報に従ってください。」と書いています（どの状態でも常に見えます）
  - 右下：出典の1行（常に表示）。押すと詳細が開きます（[出典表示の部品](#出典表示の部品)）
  - 全体の地図は、画面の左側（右の列より左）いっぱいに、できるだけ大きく、左右の中央に収まるように自動で配置します。避けるのは、右の列、右上のパネル、右下の出典の1行だけです。各段の右脇にレイヤー名が出ます。右の列は常に同じ幅を占めるので、探針を置いても、固定しても、解除しても、全体の地図の大きさも位置も変わりません
- 主な操作
  - レイヤー間隔のスライダー（間隔0で重ね合わせ、広げると分解）
  - 探針：カーソル位置を全レイヤーに貫く垂直線と、右の列に出るその地点の各レイヤーの値
  - クローズアップ：固定した探針の周辺を拡大した積層と、円の中の集計（その地点の値と並ぶ表）。半径は 1・2・5 km。固定した探針は、全体の地図の印のドラッグか、クローズアップの中のクリックで動かせる
  - レイヤーの並べ替え・表示切替・単独表示（真上からの2D表示）
  - 断面：2点を結ぶ線（または例の線のボタン）で全レイヤーを縦に切り、線に沿った変化を、全体の地図の中に立てたグラフと、右の列のグラフで見る
  - 視点の回転・パン・ズーム、視点のボタン（真上・斜め・正面、左右へ45度ずつ回す）

## 操作

### 視点のボタン

画面右上のパネルの最上部、「視点」の行です。ドラッグで崩した視点を、見やすい角度へ戻す手段にもなります。

| ボタン | 視点 |
| --- | --- |
| 真上 | 真上から見下ろす（`rotationX` 90 度、北が上） |
| 斜め | 初期表示と同じ角度（傾き 20 度、方位 45 度） |
| 正面 | 南側から低い角度（傾き 12 度、方位 0 度）で見る。平面が薄い帯になり、5枚が上下に並んで読める |
| 左へ回す / 右へ回す | 方位を 45 度ずつ回す。傾きは保つ。「右へ回す」は、見下ろした地図が時計回りに回る向き。8回で元の方位に戻る |

- どのボタンも、約0.7秒のアニメーションで視点が移ります。移った先で、積層がパネルを避けて画面に収まるよう、拡大率と位置も合わせ直します。ボタンで移った後は、画面の大きさやレイヤー間隔の変化に合わせて、自動で収め直す状態に戻ります。
- 「真上」「斜め」「正面」は、いまの視点がその角度と一致している（傾きと方位が 0.5 度以内。方位は 360 度の違いを区別しない）あいだ、選択中の見た目になります。ドラッグ・パン・ズームで動かすと、選択中の表示は消えます。
- 単独表示のあいだは、2D 表示に固定されるので、ボタンは押せません（薄く表示され、押せない状態になります）。単独表示を解除すると押せます。
- キーボードの Tab で移り、Enter かスペースで押せます。「左へ回す」「右へ回す」には、読み上げ用の説明（「左へ回す（45度）」）が付いています。

### レイヤー間隔のスライダー

画面右上の「レイヤー間隔」。左端（0 km、「重ねる」）で全レイヤーが同じ高さに重なり、右へ動かすと間隔が広がります（右端は 20 km、100 m 刻み、初期値は 12 km）。ドラッグ中は積層の高さが指に追従し、キーボードの矢印キーでも動かせます。

### 視点

| 操作 | 動き |
| --- | --- |
| 左ボタンのドラッグ | 回転（左右で水平方向、上下で傾き） |
| 右ボタンのドラッグ、または Shift を押しながら左ボタンのドラッグ | パン（平行移動） |
| マウスホイール | ズーム |

- 傾きは、ほぼ真横（8度）から真上（90度）までです。初期値は 20 度、水平方向の回転は 45 度です。ズームと注視点にも範囲があり、描画範囲の外へはパンできません。
- 視点を自分で動かすまでは、画面の大きさやレイヤー間隔に合わせて、積層全体が収まるように自動で調整します（右の列と右上のパネルを避けます）。右の列は中身がなくても同じ幅を占めるので、探針を置く・固定する・解除するときに、大きさ（zoom）も位置（target）も変わりません。
- 収める範囲は、描画範囲の外枠（正方形）ではなく、23区のデータのある範囲（外枠より小さい凸多角形。`src/config.ts` の `DATA_OUTLINE`）です。外枠の、データのない角は、右の列の下に少し入ることがあります。レイヤー名は、データのある範囲の右の縁に付くので、隠れません。23区のデータは、右の列の左の空き領域の左右の中央に置きます（レイヤー名のぶんだけ右に空けます）。

### 探針

積層の平面にカーソルを置くと、カーソルの下の地点を全レイヤーに貫く垂直線（探針）と、その地点の区名と各レイヤーの値が、画面右の列（[選んだ地点の情報の列](#選んだ地点の情報の列)）に出ます。

平面は画面上で一部重なるので、カーソルの位置がどの段の地点かは、上の段から順に調べて決めます。カーソルの位置がその段の23区の中に当たる最初の段を採用し、探針はその段の地点から垂直に立ちます。どの段でも23区の外のときは、描画範囲（`EXTENT`）に入る最も上の段を採用します。

- **カーソルを置く**：水色の探針がカーソルに追従します。
- **クリック**：探針をその地点に固定します（橙色、「● 固定中」）。固定中はカーソルを動かしても値が変わりません。固定中に平面の別の地点をクリックすると、中心がその地点に移ります。
- **ドラッグで動かす**：固定した探針の印（各段の輪と垂直線）にカーソルを合わせると、カーソルが「移動」の形（矢印が四方に出た形）に変わります。そのままドラッグすると、印がカーソルに付いてきて、中心の地点が動きます。つかんだ段（カーソルにいちばん近い輪の段。垂直線をつかんだときも同じ）の平面の上を動き、つかんだ位置と印のずれは保たれます。描画範囲の外へは出ません。ドラッグ中は、右の列の値、クローズアップ、集計が追従します（地点の更新は、描画のフレームごとに最後の1回だけ）。印の上でないところからのドラッグは、これまでどおり視点の回転です。
- **解除**：Esc キー、平面の外をクリック、または右の列の最上部（「地点」「断面」の切り替えの右端）の「消す」ボタン。解除後はカーソルを動かすと、再び追従します。
- 探針は、表示中のレイヤーだけを貫きます。非表示のレイヤーや、単独表示のときの他のレイヤーは対象になりません。
- 各レイヤーの値（切り替えにかかわらず、すべて読めます）
  - 標高：標高（m）
  - 浸水：「洪水の深さ」「高潮の深さ」「洪水の継続」「高潮の継続」の4つを、ランクのラベル（「3〜5m」「1週間〜2週間」など）で。浸水がなければ「浸水なし」、深さ 0.5m 未満の所の継続時間は「なし（浸水が 0.5m 未満）」、23区の外は「—」。高潮の継続時間の最上段は「1週間以上（上限なし）」です（洪水の同じランク 5 は「1週間〜2週間」で、意味が違います）
  - 人口：人口、65歳以上（秘匿されたメッシュは「不明（秘匿）」、周辺の秘匿分を含むメッシュは、そのことを添える）、人口密度
  - 公共交通：最寄り駅、通る路線
  - 避難：洪水・高潮で使える最寄りの避難場所（名前、区、洪水か高潮か、距離）、最寄りの病院、「この区のデータ」（その地点の区が、データ未公開・浸水が深いのに洪水・高潮用の指定がない・浸水が小さく洪水・高潮用の指定がない、のどれかのときだけ。[文言](#避難場所の指定のない区3通りの書き分け)）
- レイヤー名と同じ項目名（人口の「人口」、標高の「標高」）は、二重にならないよう項目名を省いて値だけを出します。
- 地点のローカル座標（[座標系](#座標系全データ共通)）を m 単位で、右の列に出します。

### クローズアップ

探針を固定しているあいだ、右の列（右上のパネルの左）の上に、クローズアップが出ます。固定した地点を中心とする円の範囲だけを拡大した、もう1つの積層です。全体の地図では 1 px が約 70 m で、周辺の駅や避難場所は個別に見分けられません。クローズアップは、全体と同じ見方（同じ段の順番、同じ視点の角度）のまま、縮尺だけを変えて、その地点の周辺を読めるようにします。右の列の表では、「この地点」の値と、このクローズアップの「その周辺の合計」を並べて見比べられます。

- **出る・消える**：探針を固定する（平面をクリックする、または URL の `probe`）と出ます。固定を解除する（Esc、平面の外をクリック、右の列の「消す」）と消え、同じ場所に、区名と「この地点」の値だけが残ります。右の列は常に同じ幅を占めるので、全体の積層は出ても消えても動きません。
- **中心を動かす**：クローズアップを出したまま、固定した地点（クローズアップの中心）を動かせます。
  - 全体の地図で、別の地点をクリックする。
  - 全体の地図で、固定した地点の印をドラッグする（[探針](#探針)）。ドラッグ中、クローズアップと集計が追従します。
  - クローズアップの中の平面をクリックする。クリックした画面上の位置の、その段の地点が、新しい中心になります（円の外は何も起きません）。上の段から順に、円の中に当たる最初の段を採用します。円の中ではカーソルが十字になります。
- **見出し**：列の上に、固定した地点の区名（23区の外なら「区の外」）、「● 固定中」、地点の座標が出ます。解除は、Esc か、列の最上部の右端の「消す」ボタンです。
- **半径**：クローズアップの上の「1 km」「2 km」「5 km」で切り替えます（既定は 2 km。URL の `radius` でも指定できます）。
- **各段に描くもの**：切り出したデータ（標高・浸水・人口・公共交通・避難）、円の縁の線（橙）、円で切った区の境界線、固定した地点を全段に貫く垂直線と印（全体の地図の探針と同じ見た目）、各段の右脇のレイヤー名。
  - 人口は、メッシュの中心が円の中にあるものを丸ごと描くので、円の縁でメッシュが少しはみ出します。標高は円の外を描かず、水面など標高のデータがない所（皇居の堀など）は抜けて見えます。
- **全体の地図との連動**：段の順番、表示・非表示、単独表示、視点の角度（見下ろしと方位。視点のボタンやドラッグで全体の視点を変えると、クローズアップも同じ角度になります）、レイヤー間隔。クローズアップの中では、ドラッグでの回転・パンや、カーソルでの探針は受け付けません（クリックは中心の移動になります）。視点を変えたいときは、全体の地図の側か、視点のボタンで変えます。
- **間隔の比率**：全体の地図での「間隔 ÷ 平面の幅（36 km）」と、クローズアップでの「間隔 ÷ 円の直径」が同じになるようにします。たとえば間隔 12 km・半径 2 km なら、クローズアップの間隔は約 1.33 km です。
- **範囲を示す円**：全体の地図の各段にも、切り出している範囲を橙の細い線の円で描きます。半径を変えると円の大きさも変わります。
- **集計**：クローズアップの下の表の、「半径 ○ km 内」の列に、表示中の各レイヤーの集計を、全体の地図の段の順（上の段から）に並べます。値がない項目は「—」で、数値には桁区切りを入れます。

| レイヤー | 集計の項目 |
| --- | --- |
| 標高 | 標高（円の中の最小〜最大）、平均 |
| 浸水 | 深さ（または継続時間）の区分ごとの**面積の割合**（円の中の、23区内の 50 m セルの数に対する割合。0 の区分は出さない）。切り替え（想定・見るもの）に従う |
| 人口 | 人口（メッシュの人口の合計）、65歳以上（秘匿のメッシュを除く合計）、65歳以上が不明のメッシュの数、人口密度 |
| 公共交通 | 駅の数、路線の数 |
| 避難 | 洪水・高潮で使える避難場所の数、それ以外の避難場所の数、病院の数。円がかかる区に、データ未公開の区、浸水が深いのに洪水・高潮用の指定がない区、浸水が小さく洪水・高潮用の指定がない区があれば、その名前（種類ごとに） |

表の下に、円の中の「浸水が想定される区域に住む人」（深さの区分ごとの人口と65歳以上人口、標高 0m 未満の土地の人口）を、23区全体と同じ表で出します（[集計の数え方](#集計の数え方浸水が想定される区域に住む人)）。想定の切り替えに従います。

- **画面の配置**：[選んだ地点の情報の列](#選んだ地点の情報の列)の、見出しと表のあいだの部分です。表に使った残りの高さを、クローズアップが使います（最小 120 px）。全体の積層の描画領域は、右上のパネルの左の全体で、列はその右端に重なります。
- **切り出しの頻度**：円で切り出すのは、固定した地点か半径が変わったとき、レイヤー一覧の切り替えが変わったときだけです。視点の角度やレイヤー間隔を変えても、切り出し直しません（実データで、半径 2 km で約 10 ms、5 km で約 20 ms）。印のドラッグ中は、マウスの移動のたびではなく、描画のフレームごとに1回だけ切り出します。

### 断面

探針とクローズアップに並ぶ、3つ目の読み方です。探針は「1地点の値」、クローズアップは「円の範囲の拡大と集計」で、断面は「線に沿った変化」を見せます。たとえば新宿の台地から江戸川区の低地へ線を引くと、標高が海面より下がる区間、浸水が深くなる区間、人が多く住む区間、避難場所のある区間・ない区間（データのない区間）が、上下に並びます。

**線を引く手がかり（例の線）**：「断面」に切り替えて、まだ線を引いていないとき、右の列に、例の線を1クリックで引けるボタンを3つ出します（`src/section/examples.ts`）。実データ（標高・浸水想定・避難場所）で、この地図の主題（低地の浸水、人口、避難場所の空白）がよく出る線を選びました。

| ボタン | 線（ローカル座標 A → B） | 見えること |
| --- | --- | --- |
| 台地から低地へ（新宿 → 江戸川区役所） | (-4471, 1066) → (10706, 2969)、15.3 km | 東西。台地（標高 20m 以上）から、海面より低い江戸川区へ。標高が 0m を下回る区間は線の約 25%、浸水 3m 以上の区間は約 36%（5.5 km）。その区間から 1 km 以内の洪水・高潮用の避難場所は 24 か所で、東の端（江戸川区）にはない。途中に、浸水が小さく指定がない区（新宿）、データ未公開の区（墨田・江東）、浸水が深いのに指定がない区（江戸川）を通る |
| 荒川を横切る（北区 → 北千住 → 足立・葛飾） | (-4500, 7740) → (11760, 7740)、16.3 km | 東西。荒川・隅田川を越えて、海面より低い土地（線の約 17%）が続き、浸水 3m 以上が線の約 64%（10.5 km）。その区間から 1 km 以内の洪水・高潮用の避難場所は 28 か所だが、西の台地側と荒川の西側にあり、荒川の東側の低地にはほとんどない |
| 低地を南北に（足立 → 荒川 → 墨田 → 江東） | (4968, 11100) → (4968, -4440)、15.5 km | 南北。ほぼ全線で浸水が想定される低地（浸水 3m 以上が線の約 62%、9.7 km）を、データ未公開の区（墨田・江東）を通って、東京湾へ。浸水 3m 以上の区間から 1 km 以内の洪水・高潮用の避難場所は 13 か所だけ |

- 選んだ理由：候補の線ごとに、標高 0m 未満の割合、浸水 3m 以上の割合、線から 1 km 以内の洪水・高潮用の避難場所の数と並び（`S`）を、25〜250 m 刻みで数えて比べました。東西は、台地から始まる線（新宿 → 江戸川区役所、池袋 → 葛西）が「台地 → 低地」の変化を見せ、北千住の東西の線は、低地が続く中で荒川を越える所に、浸水の深い区間と避難場所の空白が重なります。南北の線は、避難場所のデータがない区を連続して通ります。


右の列の上部の「読み方」で、「地点」（これまでどおり、探針とクローズアップ）と「断面」を切り替えます。「断面」のあいだ、全体の地図での操作は、線を引く操作になります。「地点」へ切り替えても、引いた線は消さずに保持し、「断面」へ戻すと再び出ます（固定した探針も同じです。「断面」のあいだは、探針とクローズアップは出ません）。

**線を引く・動かす**（`src/section/interaction.ts`、`src/section/controller.ts`、`src/section/lineDrag.ts`）

| 操作 | 動き |
| --- | --- |
| 平面を1回クリック | 始点（A）を置く。置いたあとは、カーソルの位置まで線の下書きが出る |
| もう1回クリック | 終点（B）を置いて、線を決める（始点から 300 m 未満のときは決まらない） |
| 両端の印をドラッグ | その端点だけが動く（つかんだ段の平面の上を、描画範囲の中で動く） |
| 線の上をドラッグ | 線全体が平行に動く（向きと長さは変わらず、両端が描画範囲に収まるまで） |
| 端点と線の外をクリック | いまの線が消え、そこが新しい始点になる（引き直し） |
| Esc、または右の列の「消す」 | 線（と、置きかけの始点）を消す |
| 印や線の外からのドラッグ | これまでどおり、視点の回転 |

- 平面の上のカーソルは十字になり、印や線の上では「移動」の形になります。クリックした地点がどの段のものかは、[探針](#探針)と同じ規則（上の段から順に、23区の中に当たる最初の段）で決めます。
- 線の向きは A から B です。線の進行方向に向かって左を「左」、右を「右」と呼びます（東向きの線なら、北が左）。
- 線を引くと、各レイヤーの値を `registry[id].section(data, line)`（`src/layers/`）で取り出します。実データで全5レイヤー合わせて 1 ms 前後なので、端点のドラッグ中も、描画のフレームごとに計算し直します。

**全体の地図の中の表現**（`src/section/sectionLayers.ts`）

- 表示中の全段に、白い切り口の線を描きます。始点 A は塗りの丸、終点 B は輪で、両端を全段に貫く細い白の垂直線と、いちばん上の段の上に「A」「B」の札が付きます（右の列のグラフの左端が A、右端が B です）。
- 各段の線の上に、その段のトラックを、切り口に沿って垂直に立てます。
  - 標高・浸水・人口（系列）：平面から立ち上がる帯（面グラフ）。色は平面と同じ配色で、値がない区間（川など）は帯を描きません。帯の上の縁は白い線で引きます。縦の範囲は、右の列のグラフと同じです（標高は -5〜50 m、人口密度は 0〜40,000 人/km²、65歳以上の密度は 0〜12,000 人/km²、浸水は段の数で、深さは6段・継続時間は想定に応じて5〜9段）。浸水は、段の位置が高さになる階段で、色は平面の配色です。人口密度が上端 40,000 を超える区間は、帯を上端で止めて、そこに白い太線を引きます（右の列のグラフも同じで、最大の実際の値は、グラフの要約の横に出ます）。
  - 公共交通・避難（交差と地物）：その位置に立つ柱。色は平面の配色です。線から離れた地物（駅、避難場所、病院）は、**地物の位置に柱を立て**、線の上の同じ距離の地点から地物までを、平面の上に細い線でつなぎ、柱の先に丸を付けます。右の列のグラフの縦方向（線からの距離）が、地図の上では実際の位置のずれとして見えます。
- 立てるグラフの高さは、レイヤー間隔の 65%（間隔 12 km で 7.8 km、20 km で 13 km）で、1つ上の段の平面の手前に収まります。間隔に比例して縮め、間隔が 920 m 未満（高さが 600 m 未満）のとき、間隔が 0 のときは立てません。高さの基準になる範囲（立てられる高さ全体）は、各段にごく薄い面で示します。
- 立てたグラフは半透明（帯の塗りは不透明度 59%）で、奥の段のデータが透けて読めます。描く順は、各段の平面、その段のデータ、区の境界線のあとで、立てるグラフ、切り口の線と端点の順です。1つ上の段の平面より前には描かないので、上の段のデータが前に重なります。
- 視点を回して切り口を正面から見ると（視点のボタン「正面」で、東西の線を見るとき）、右の列のグラフと同じ形に見えます。線の延長方向から見ると、立てたグラフは細い線になり、真上からは線と端点だけが見えます。
- 単独表示（真上からの2D）のあいだは、切り口の線と端点だけを描きます。

**右の列のグラフ**（`src/section/SectionPanel.tsx`、`src/section/model.ts`、`src/section/alignment.ts`、`src/section/tierScreen.ts`）

- 見出しに、「断面」、線の長さ（km）、始点 A と終点 B の区名（23区の外なら「区の外」）が出ます（列の最上部、「地点」「断面」の切り替えの下）。
- **線に沿った集計**：グラフの下に、「浸水 3m 以上：○ km（線の ○%）。その区間から 1 km 以内の、洪水・高潮用の避難場所：○ か所」を出します。浸水の深さは、想定の切り替え（大きいほう・洪水・高潮）に従います。区間は、線に沿って 25 m ごとに浸水の深さの段を引き、段が変わる位置を二分法で詰めて求めます。距離は、区間（線の一部）から避難場所までの直線距離です（`src/aggregate/sectionExposure.ts`）。「消す」ボタンは、切り替えと同じ並びの右端にあります。
- 表示中の各レイヤーのグラフが、右の列に縦に並びます。横軸は全グラフ共通の、線に沿った距離（km。左端が A、右端が B）で、**いちばん下のグラフの下に1つだけ**出ます。全グラフで、枠の左右の位置が揃います。
  - 標高：面グラフ（縦軸は m）。人口：階段状の面グラフ（縦軸は人/km²）。どちらも色は平面と同じ配色です。
  - 公共交通：路線との交差の縦線と、近くの駅（線から 500 m 以内）の点。点の縦の位置が線からの距離で、上が左、下が右です。
  - 浸水：段の階段（面グラフ）。縦軸は、段のラベル（深さなら「<0.5」「0.5-3」「3-5」「5-10」「10-20」「20+」（m）、継続時間なら「<12h」「1-3日」「1週+」など）を、その段の高さに出します。段が詰まって読めないときは、上の段を残して間引き、カーソルを置くと名前が全文で出ます。
  - 避難：線から 1 km 以内の避難場所と病院の点。洪水・高潮で使える避難場所（大きな緑の丸）、それ以外の避難場所（小さな灰色の丸）、病院（赤いひし形）で見分けます。縦の位置は線からの距離です。線が通る区のうち、洪水・高潮で使える避難場所のない区の区間を、3通りに書き分けてグラフの上に示します（[避難場所の指定のない区](#避難場所の指定のない区3通りの書き分け)）：灰の斜線（「データ未公開」）、琥珀の斜線と太い縁（「浸水が深いのに指定なし」。この地図の主題なので、いちばん目立つ）、薄い点線の枠（「指定なし（浸水小）」。目立たない）。区間にカーソルを置くと、区名と文が全文で出ます。
- 各グラフの左（幅 58 px）に、レイヤー名を枠の縦の中心に合わせて置きます。縦軸の目盛りは、枠の右（幅 58 px）です。枠の上（最大2行、30 px。枠の高さには含めません）に、そのレイヤーの要約を添えます：標高の最小〜最大、浸水の最大の段、人口密度の最大、路線との交差の数と近くの駅の数、避難場所（洪水・高潮用・それ以外）と病院の数。カーソルを置いているあいだは、同じ場所に、その位置の値が出ます（要約に代わります）。
- 線の外（23区の外）は標高も人口密度も値がありません。人口密度の縦軸は 40,000 までなので、これを超える区間は頭打ちで、その旨を要約の横に出します。

**段とグラフの対応：同じ高さに置く**

段とグラフの対応は、線でつなぐのではなく、位置で読ませます。全体の地図の各段の右脇のレイヤー名から、目を真横に動かすと、同じ高さに、同じ名前のグラフがあります（静止した画面に、線や色分けを足しません）。

- **揃える**：各グラフの枠の縦の中心を、対応する段の平面の中心（全体の地図で、レイヤー名と同じ高さ）の画面上の高さに置きます。段の順がグラフの順なので、並べ替えるとグラフも入れ替わります。非表示の段のグラフは出ません。
- **枠の高さ**：5つとも同じ高さです。隣の段との間隔（段の高さのアニメーションが終わったあとの値）から、要約の行（30 px）と隙間（8 px）を引いた高さに、上限 72 px、下限 46 px を掛けます。いちばん上と下の段が列の端に近いときは、そのグラフが列から出ない高さまで縮めます（46 px まで）。たとえば、2000×1100 の斜めの視点で、間隔 12 km なら、段の間隔は約 188 px で、枠は上限の 72 px、1400×1000 なら、約 170 px の間隔で、いちばん上の段が見出しに近いぶん、枠は 70 px です。
- **追従**：間隔のスライダー、段の並べ替え・表示切替、視点の変更（ボタンとドラッグ）、拡大・パン、ウィンドウの大きさの変化に合わせて、グラフが段と一緒に動きます。アニメーション中の段の高さ（`useDisplayedZ`）に合わせて、毎フレーム動きます。全体の地図（`StackView.tsx`）が、段の高さと視点を `tierScreen.ts` に公開し、右の列がそれを読んで位置を決めます（順番に並ぶので、並べ替えの途中で段が入れ替わっても、グラフは重ならずに順番を保って移ります）。
- **列に収める**：拡大・パンで段が列の表示範囲の外（見出しの下〜横軸の上より上や下）へはみ出すときは、グラフを列の中へ寄せます。順番と、隣との間隔は保ちます。このときは、段の高さとのずれが出ます。間隔が 20 km だと、いちばん上の段が見出しに近いので、いちばん上のグラフは、約 20 px 下へ寄ります（2000×1100）。
- **縦並びに切り替える**：次のときは、これまでどおり、上から順に、同じ高さ（40〜64 px）の枠を縦に並べます。
  - 隣の段との間隔が狭く、要約と隙間を除いて、枠が 46 px 入らない（間隔が約 3.5 km より狭い。2000×1100、斜めの視点）。真上の視点（段が画面上で重なる）、間隔 0 もこれにあたります。
  - 段が1枚だけ（単独表示、2枚非表示）、または、領域にすべてのグラフが入らない。
  - 縦並びから揃えるへ戻るときは、さらに 8 px の余裕（間隔が約 3.9 km 以上）を見ます。境目で、行き来を繰り返しません。この判定は、アニメーションの途中の高さではなく、落ち着いたあとの高さ（視点が自動で収め直されるときは、収め直したあとの視点）で行うので、間隔や視点の変化の途中の揺れでは切り替わりません。
  - 切り替えの直後の 0.45 秒だけ、グラフは滑らかに移ります（跳ねません）。

**連動**

- 右のグラフにカーソルを置くと、全グラフに共通の水色の縦線（と、標高・浸水・人口では線の上の丸）が出て、その位置の値（標高、浸水の段の名前、人口密度、いちばん近い交差・駅・避難場所・病院の名前と、駅や避難場所・病院は線からの距離と向き）が、各グラフの枠の上に読めます。同時に、全体の地図の、線の上の同じ位置に、全段を貫く水色の垂直線と各段の輪が出ます（探針と同じ見た目）。
- 右のグラフにカーソルを置くと、**そのグラフの対応する段が目立ちます**。そのグラフの枠が水色になり、名前が白くなります。全体の地図では、その段をそのままに、ほかの段が暗くなります（各段の描画の不透明度に 0.38 を掛けるだけで、データや属性は作り直しません）。カーソルを外すと元に戻ります。
- 逆に、全体の地図で切り口の線（と、その上に立てたグラフ）の近く（14 px 以内）にカーソルを置くと、右のグラフの同じ位置に縦線が出て、その段の**対応するグラフが目立ちます**（枠が水色、名前が白）。このとき、全体の地図の段は暗くしません。
- どちらのカーソルもないとき（静止した画面）は、強調も暗い段もありません。

### 選んだ地点の情報の列

画面右、右上のパネルのすぐ左にある、画面の高さいっぱいの列です。幅は、右上のパネルを除いた画面の幅の 33%（380〜560 px）で、中身の有無にかかわらず常に確保します（`src/info/InfoColumn.tsx`）。下端は、右下の出典の1行のぶん（30 px）空けます。探針の状態で、中身が3通りに変わります。

| 状態 | 列の中身 |
| --- | --- |
| 探針がない | 23区全体の主な数字と表（[見せ方](#23区全体の集計の見せ方)）。その下（列の下端、スクロールの外）に操作の手がかり（平面にカーソルを置くと値が読める、クリックで固定するとクローズアップが出る）。その下に、試作の注意 |
| カーソルを置いただけ | 区名、座標、表（「レイヤー」「この地点」）。カーソルを動かすと値が追従する |
| 固定している | 区名・「● 固定中」、座標と半径のボタン、クローズアップ、表（「レイヤー」「この地点」「半径 ○ km 内」） |

- **表**：行は、表示中のレイヤーを全体の地図の段の順（上の段から）に並べます。「この地点」は探針の値、「半径 ○ km 内」は円の中の集計で、同じレイヤーの行で左右に並びます（行の見出しとして、レイヤー名と同じ項目名は省きます）。値がない項目は「—」、読み込み中は「読み込み中…」、失敗は「読み込み失敗」です。数値には桁区切りと単位を付けます。
- **折り返し**：長い路線名や避難場所の名前は、語の途中ではなく、文節などの区切りで折り返します（CSS の `word-break: auto-phrase`。区切りがなければ、はみ出さないよう折ります）。
- **スクロール**：中身が画面の高さに収まらないときは、表の部分だけがスクロールします。見出しとクローズアップは常に見えます（表は列の高さの 52% まで）。表の見出し行（「レイヤー」「この地点」「半径 ○ km 内」）は、スクロールしても固定されます。

### レイヤー一覧

画面右上、スライダーの下。上が最上段です。

- **並べ替え**：左端のつまみ（⠿）をドラッグする。つまみにフォーカスして上下キーでも動かせる。▲▼ボタンで1段ずつ動かすこともできる。ドラッグ中に Esc で取り消す。
- **表示切替**：レイヤー名のチェックボックス。非表示にしたレイヤーのぶんは積層から詰まります。
- **単独表示**：「単独表示」ボタン。そのレイヤーだけを真上（北が上）から見た2D表示に切り替えます（ボタンは「単独表示中」になる）。もう一度押すか、一覧の上に出る「積層表示に戻る」で、元の視点に戻ります。

## URL クエリ

URL のクエリで、初期状態を指定できます。画面を操作して決めた状態を共有したり、スクリーンショットを再現したりするときに使います。数値でない値やレイヤーID でない値は無視して既定値を使い、範囲のある数値は上下限に丸めます（例：`spacing=-5` は 0、`rx=999` は 90）。

| クエリ | 値 | 意味 |
| --- | --- | --- |
| `data` | `fixture` | `public/data-fixture/` の仮データを読む。`fixture` 以外の値、省略時は `public/data/` |
| `spacing` | 数値（m） | レイヤー間隔。0〜20000 に丸める。既定 12000 |
| `order` | レイヤーIDをカンマ区切り | 積層の順（**下から上**）。書かなかったレイヤーは、既定の順で後ろ（上）に続く。例: `order=shelters,transit` は下から 避難・公共交通・標高・浸水・人口 |
| `hidden` | レイヤーIDをカンマ区切り | 最初から非表示にするレイヤー |
| `solo` | レイヤーID | 最初から単独表示にするレイヤー（真上からの2D表示で始まる） |
| `probe` | `x,y` | 探針をその地点に固定した状態で始める。**ローカルのメートル座標**（経緯度ではない）。2つの数値が必要 |
| `rx` | 数値（度） | 傾き。8（ほぼ真横）〜90（真上）に丸める。既定 20 |
| `ro` | 数値（度） | 水平方向の回転。範囲の制限はない。既定 45 |
| `zoom` | 数値 | ズーム（2のべき乗。値が1増えると倍率が2倍）。-9〜-1 に丸める。指定すると、積層を画面に収める自動の拡縮合わせは行わない。省略時は自動 |
| `section` | `ax,ay,bx,by` | 断面の線を引いた状態で、「断面」に切り替えて始める。始点 (ax, ay) と終点 (bx, by) の**ローカルのメートル座標**（経緯度ではない）。4つの数値が必要で、長さが 300 m 以上のとき有効（それ以外は無視して「地点」で始まる）。`probe` と一緒に指定すると、固定した探針も保持する |
| `flood` | `max` / `river` / `tide` | 浸水の**想定**。`max` = 洪水と高潮の大きいほう（既定）、`river` = 洪水、`tide` = 高潮。ほかの値は既定 |
| `floodview` | `depth` / `duration` | 浸水で**見るもの**。`depth` = 深さ（既定）、`duration` = 水が引くまでの期間（浸水継続時間）。ほかの値は既定 |
| `pop` | `total` / `elderly` | 人口で**見るもの**。`total` = 総人口（既定）、`elderly` = 65歳以上（人口密度で塗る）。ほかの値は既定 |
| `radius` | 数値（m） | クローズアップの半径。`1000`・`2000`・`5000` のどれか。それ以外の値（ほかの数値、数値でない値）は既定の 2000 に戻す。クローズアップは探針を固定しているあいだだけ出るので、`probe` と組み合わせて使う |

レイヤーID は `elevation`（標高）、`flood`（浸水）、`population`（人口）、`transit`（公共交通）、`shelters`（避難）です。

既定値は、間隔 12 km、傾き 20 度、回転 45 度、全レイヤー表示、探針なし、積層表示、実データ、クローズアップの半径 2 km、「地点」（断面の線なし）、浸水は「大きいほう」の「深さ」、人口は「総人口」です。

例：

```
?data=fixture&spacing=8000&order=shelters,transit&hidden=population&rx=40&ro=20
?flood=tide&floodview=duration&solo=flood
?pop=elderly
?probe=10706,2969
?probe=5811,1810&radius=2000
?section=-4471,1066,10706,2969&flood=river
?solo=elevation
?probe=1548,133
?probe=1550,130&radius=5000
?section=-15000,-2000,14000,-2000
?section=-15000,-2000,14000,-2000&rx=12&ro=0
?section=-4471,1066,10706,2969&rx=12&ro=0
```

## 技術構成

- Vite + React + TypeScript + deck.gl 9、状態管理は zustand
- 3Dビューは deck.gl の `OrbitView`（`orthographic: true`）
- 地理データは前処理でローカルのメートル座標に変換し、画面側は `COORDINATE_SYSTEM.CARTESIAN` で描画します
- 前処理は `scripts/` 配下の Node.js（ESM）スクリプトで行い、生成物を `public/data/` に置きます
- ダウンロードした元データは `.cache/` に置き、Git には含めません
- 画面側のソースは `src/` にあります
  - `src/App.tsx`：画面の部品（積層ビュー、右の列、右上のパネル、出典表示）の配置
  - `src/store.ts`：状態（zustand）と URL クエリの読み取り。`src/config.ts`：描画範囲、間隔・視点の上下限などの定数
  - `src/aggregate/`：レイヤーをまたぐ集計（`exposure.ts` が、人口のメッシュと浸水想定から、浸水が想定される区域に住む人を数える。`wardExposure.ts` が、区ごとの割合と、洪水・高潮用が 0 件の区の分類・概数の表記を求める。`sectionExposure.ts` が、断面の線に沿った、浸水 3m 以上の区間と、その近くの避難場所を数える）
- `src/section/`：断面（`interaction.ts` が線を引く手順・つかむ判定・ドラッグの計算、`lineDrag.ts` がそれを DOM のポインタ操作につなぐ部分、`controller.ts` が地図の上のカーソルとクリック、`model.ts` がグラフの座標の換算・目盛り・値の読み取り・面グラフの形・要約、`sectionLayers.ts` が全体の地図に描くレイヤー、`SectionPanel.tsx` が右の列のグラフ、`alignment.ts` がグラフを段と同じ高さに置く計算と縦並びへの切り替えの判定、`tierScreen.ts` が全体の地図から右の列へ渡す各段の画面上の位置、`tracks.ts` が各レイヤーの `section` の呼び出し）
  - `src/view/`：3D ビュー、カメラ、積層の配置の計算。`src/layers/`：レイヤーごとの描画と値（`flood/` が浸水の段・配色と格子の計算、`shelters/` が避難場所・病院・網掛け・区の3通りの書き分けの描画と文言）。`src/aggregate/`：レイヤーをまたぐ集計（`exposure.ts` が、人口のメッシュと浸水想定から、浸水が想定される区域に住む人を数える。`wardExposure.ts` が、区ごとの割合と、洪水・高潮用が 0 件の区の分類・概数の表記を求める。`sectionExposure.ts` が、断面の線に沿った、浸水 3m 以上の区間と、その近くの避難場所を数える）。`src/probe/`：探針（`markDrag.ts` は、固定した印をつかんで動かす操作）。`src/closeup/`：クローズアップ（円形の積層の部品、円で切り出す処理、視点と間隔の計算、円の描画）。`src/info/`：右の列（`InfoColumn.tsx` が部品、`infoModel.ts` が表の行や列の中身を決める計算）。`src/panel/`：右上のパネルと出典表示

## 座標系（全データ共通）

横メルカトル図法のローカル座標で、単位はメートルです。

```
+proj=tmerc +lat_0=35.68 +lon_0=139.75 +k=1 +x_0=0 +y_0=0 +ellps=GRS80 +units=m +no_defs
```

- `x` は東向き、`y` は北向き。原点は東経139.75度・北緯35.68度
- 描画範囲（`EXTENT`）は 36km 四方の正方形：`minX=-19000, minY=-19000, maxX=17000, maxY=17000`
- ベクタデータの座標は 1m 単位に丸めます
- レイヤーの高さ（z）は画面側で与えるため、データには含めません

## データ仕様（`public/data/`）

ベクタデータは GeoJSON の FeatureCollection 形式で、`coordinates` に上記ローカル座標を入れます。

| ファイル | geometry | properties |
| --- | --- | --- |
| `boundary.geojson` | Polygon / MultiPolygon（区ごとに1 Feature） | `code`（市区町村コード5桁）, `name`（区名） |
| `population.geojson` | Polygon（メッシュ1個ごと。4隅をたどって始点に戻る5点の閉じたリング） | `meshCode`, `population`（人）, `density`（人/km²）, `elderly`（65歳以上人口。人）, `elderlyMerged`（真偽値） |
| `roads.geojson` | LineString | `class`（`motorway` / `national` / `prefectural` / `other`）, `name`（なければ null） |
| `rail.geojson` | LineString | `operator`（事業者名）, `line`（路線名） |
| `stations.geojson` | Point | `name`（駅名）, `operator`, `line` |
| `facilities.geojson` | Point | `kind`（`school` / `hospital`）, `name`, `subtype`（学校は学校種別、病院は「病院」） |
| `shelters.geojson` | Point | `name`（施設・場所名）, `address`, `ward`（区名）, `flood`・`tide`・`inland`・`quake`・`fire`・`tsunami`・`landslide`（真偽値。順に 洪水・高潮・内水氾濫・地震・大規模な火事・津波・崖崩れ）, `note`（備考。なければ null） |

人口の `elderly` と `elderlyMerged`、避難場所（`shelters.geojson` と `shelters.json`）の決まりは次のとおりです。

- `elderly`（65歳以上人口）は 0 以上の整数です。
  - 秘匿されたメッシュは `null` です（国勢調査の秘匿処理。総人口 `population` は秘匿されないので、値があります）。
  - 元データに行がないメッシュ（人口 0）は 0 です。
  - `elderlyMerged` が `true` のメッシュは、秘匿処理の**合算先**です。周辺の秘匿されたメッシュの分を値に含みます。そのため、元データでは 65歳以上が総人口を上回ることがあり、その場合は総人口を上限にして丸めています（250 m メッシュで 2 件、丸めた差は合わせて 5 人）。
  - 既存の `meshCode`・`population`・`density` とメッシュの並びは変わりません。
- `shelters.geojson` は、座標が23区内にある指定緊急避難場所の全件です。`ward` は、座標から求めた区名です（元データの共通ID の区コードではありません）。並びは、洪水か高潮で使える場所が先、それ以外が後で、それぞれの中は元データの並びのままです。
- `shelters.json` は区ごとの集計です。

```
{ "updated": "2026-10-19", "total": 977,
  "wards": [ { "code": "13101", "name": "千代田区", "total": 28, "flood": 23, "tide": 21, "published": true, "updated": "2025-03-10" }, ... ] }
```

  - `wards` は23区すべてを、コードの昇順で入れます。`total` はその区の避難場所の件数、`flood`・`tide` は、洪水・高潮で使える件数です。
  - `published` は、その区がこのデータに指定緊急避難場所を公開しているか（0 件の区は `false`）です。墨田区・江東区・渋谷区・葛飾区は `false` で、指定避難所のデータだけを公開しています。「0 件」は、避難場所がないことではなく、データがないことを表します。公開している区で洪水・高潮用が 0 件の区（足立・江戸川・新宿・文京）は、画面が、区の浸水の想定で2つに分けます（[避難場所の指定のない区](#避難場所の指定のない区3通りの書き分け)）。
  - `updated` は、23区の更新日のうち最も新しいものです。区ごとの `updated` は、国土地理院の「区ごとの更新日の一覧」の最終更新日です（区により 2025-01-23 から 2026-10-19 まで）。

ファイルサイズの上限は、1ファイル 10MB、`public/data/` 全体で 30MB です（1MB = 1024 × 1024 byte）。

標高は格子データです。

- `elevation.bin`：Float32（リトルエンディアン）の格子。行は北から南、列は西から東の順。データなしは NaN
- `elevation.json`：`{ width, height, cellSize, minX, minY, maxX, maxY, min, max }`
  - 範囲は `EXTENT` と同じ、`cellSize` は 50（m）、したがって `width = height = 720`
  - `min` / `max` は23区内の有効値の最小・最大（m）
  - 各セルの値は、セルの中心での標高です。列 `col`・行 `row`（どちらも0始まり）のセルの中心は `x = minX + (col + 0.5) × cellSize`、`y = maxY − (row + 0.5) × cellSize`
  - 地点 `(x, y)` を含むセルは `col = floor((x − minX) / cellSize)`、`row = floor((maxY − y) / cellSize)`
  - 23区の外と水面はデータなし（NaN）にします

浸水想定（洪水・高潮）も格子データです（`scripts/build-flood.mjs` が作ります。画面の「浸水」のレイヤーが読みます）。標高と同じ 50 m 格子（720×720、行は北から南、列は西から東、各セルの値はセルの中心での値。セルの中心の式や、地点を含むセルの求め方は、上の標高と同じ）に、**Uint8** で入れます。

| ファイル | 内容 | 値 |
| --- | --- | --- |
| `flood-river.bin` | 洪水の浸水深ランク（想定最大規模） | 0 = 浸水なし、1〜6 = 浸水深のランク、255 = 23区の外 |
| `flood-tide.bin` | 高潮の浸水深ランク（想定最大規模）。洪水と同じ区切り | 同上 |
| `flood-river-duration.bin` | 洪水の浸水継続時間ランク | 0 = 浸水なし、1〜7 = 継続時間のランク、255 = 23区の外 |
| `flood-tide-duration.bin` | 高潮の浸水継続時間ランク | 0 = 継続時間の値なし（浸水深 0.5 m 未満を含む）、1〜5 = 高潮の継続時間のランク（下記。洪水とは表が別）、255 = 23区の外 |
| `flood.json` | 格子の範囲と、ランクの意味、出典 | 下記 |

- 255 は「セルの中心が23区の外」で、標高の NaN の範囲のうち区の外にあたる部分と同じです。区内のセルは 0〜6（洪水の継続時間は 0〜7、高潮の継続時間は 0〜5）で、**区内なら、標高が NaN の水面のセルにも値が入ります**（想定の区域に川や運河が含まれていれば、その値。含まれていなければ 0）。
- 浸水深のランク：1 = 0.5 m 未満、2 = 0.5〜3 m、3 = 3〜5 m、4 = 5〜10 m、5 = 10〜20 m、6 = 20 m 以上（下限を含み、上限を含まない。0.5 m ちょうどはランク 2）。
- 洪水の浸水継続時間のランク：1 = 12 時間未満、2 = 12〜24 時間、3 = 1日〜3日、4 = 3日〜1週間、5 = 1週間〜2週間、6 = 2週間〜4週間、7 = 4週間以上。浸水深 0.5 m 以上が続く時間です。
- 高潮の浸水継続時間のランク（`tideDurationRanks`）：1〜4 は洪水と同じ区切り（12 時間未満、12〜24 時間、1日〜3日、3日〜1週間）、**5 = 1週間以上**。6・7 は使いません。洪水の表（`durationRanks`、7 件）とは別の表なので、同じランクの数字でも、5 以上は意味が違います（洪水の 5 は「1週間〜2週間」）。
- `flood.json`：`{ width, height, cellSize, minX, minY, maxX, maxY, depthRanks, durationRanks, tideDurationRanks, files, values, tideDurationNote, sources }`
  - 範囲は `elevation.json` と同じです（`cellSize` 50、720×720）
  - `depthRanks`（6件）、`durationRanks`（洪水の継続時間。7件）、`tideDurationRanks`（高潮の継続時間。5件。5 のラベルは「1週間以上」）：`{ rank, label }`。`label` は画面に出す日本語（`'0.5m 未満'`、`'3〜5m'`、`'1週間〜2週間'` など）。区間の数値として、`minM` / `maxM`（m。最後は `maxM` が null）、`minH` / `maxH`（時間）も付いています
  - `files`：各ファイルの名前（`riverDepth`、`tideDepth`、`riverDuration`、`tideDuration`）。いずれも作ります
  - `values`：`{ none: 0, outside: 255 }`
  - `sources`：洪水（`river`）と高潮（`tide`）の出典（`name`、`publisher`、`url`、`attribution`（画面に出す出典の文面）、`vintage`、`scenario`、`notes`）
- **高潮の浸水継続時間は、1週間以上をすべてランク 5 にまとめています。** 港湾局のデータ（`shape(term).zip`。`TermMin`、分）は、浸水深 0.5 m 以上が続く時間で、洪水と同じ定義ですが、計算期間が約1週間です。1週間を超えて引かなかったセルは「未解消」の特別値（999999 分）になっており、それより長い時間は区別できません（有限の値の最大は 13,027 分 = 約9日）。区内の継続時間のあるセル（75,827。高潮の浸水深 0.5 m 以上のセルと一致）のうち、特別値が 36,834（約 49%）、1週間を超える有限の値が 161 で、ランク 5 は合わせて 36,995 セルです。洪水の 5〜7（1週間〜2週間、2週間〜4週間、4週間以上）には分けられないので、5 の「1週間以上」には**上限がありません**（実際の継続時間は 1週間より長いことしか分かりません）。値のあるセルが 0 分でも、ランク 1 にします。理由は `flood.json` の `tideDurationNote` にもあります。
- 洪水は、多角形（浸水想定区域）の内側にセルの中心が入るかで決め、重なるセルは最大のランクです。高潮は、10 m セルの浸水深の、50 m セルの中の最大から決めます。

各データは23区の範囲に絞ります（区の境界で切り抜くか、区に交差するものだけを残します）。

### 浸水の配色と区切り

- **深さ**：国のハザードマップ（浸水ナビ）で使われている浸水深の配色に揃えています（利用者が見慣れているため）。0.5m 未満 (247,245,169)、0.5〜3m (255,216,192)、3〜5m (255,183,183)、5〜10m (255,145,145)、10〜20m (242,133,201)、20m 以上 (220,122,220)。黒の背景の上で、どの段も明るく（背景とのコントラスト比 7 以上）、浅い段が沈みません。区内の、浸水がない所は、暗い灰青 (30,34,46)（23区の外は透明）。
- **水が引くまでの期間（浸水継続時間）**：深さとは別の色相（青緑 → 鮮やかな青。色相 172〜240 度）で、長いほど飽和度が上がり、濃く目立ちます。9段の色は、`src/layers/flood/classes.ts` の `DURATION_COLORS`（最短 (200,224,221) → 最長 (71,71,255)）です。
- **想定の切り替えと、継続時間の最上段**：洪水は 7 段（最上段 3つは 1〜2週間・2〜4週間・4週間以上）、高潮は 5 段（最上段は「1週間以上」。上限なし）で、最上段の意味が違います。「大きいほう」では、セルごとに2つのうち大きいほうを採り、この違いを残すために 9 段になります：12時間未満・12〜24時間・1日〜3日・3日〜1週間・1週間〜2週間（洪水）・**1週間以上（高潮。上限なし）**・2週間〜4週間（洪水）・**2週間以上**（洪水が 2〜4週間で、高潮が 1週間以上のとき。高潮に上限がないので、2〜4週間とは言えない）・4週間以上（洪水）。同じ時間の段は、想定が違っても同じ色です。凡例にも探針の値にも、「上限なし」と書いています。

### 浸水想定の前提

浸水想定（`flood*`。[データ仕様](#データ仕様publicdata)）の前提です。ハザードマップではなく、国と東京都が公表した想定を、50 m 格子にまとめたものです。

| | 洪水 | 高潮 |
| --- | --- | --- |
| 元データ | 国土数値情報 洪水浸水想定区域（A31b）2025年度版。洪水予報河川・水位周知河川と、その他の河川を重ねたもの | 東京都港湾局 高潮浸水想定区域図（令和6年12月改定） |
| 規模 | 想定最大規模（その川で想定し得る最大の降雨） | 想定最大規模（想定し得る最大の高潮。堤防等の決壊を見込む） |
| 含まないもの | 支川の氾濫、高潮、内水（雨水が下水・排水路から溢れる浸水） | 河川の氾濫、内水 |
| 浸水継続時間 | 浸水深 0.5 m 以上が続く時間 | 浸水深 0.5 m 以上が続く時間。計算期間が約1週間なので、1週間以上は区別できない（上のデータ仕様） |

- どちらも「ある1つの災害のときの、最大の浸水」です。洪水と高潮が同時に起きる場合は想定していません。2つの格子は、別々の災害の想定として読みます。
- 想定は、堤防などの施設が壊れる前提を含み、過去の実績や予報ではありません。区域の外が安全とは限りません。

## 集計の数え方（浸水が想定される区域に住む人）

この地図の主題の数字です（`src/aggregate/exposure.ts`）。

- 人口の250mメッシュごとに、**メッシュの中心**を含む浸水想定のセル（50 m）の深さのランクを引き、区分（深さ）ごとに、メッシュの人口と65歳以上人口を合計します。**メッシュの面積を浸水域で按分することはしません**（メッシュの中心がどの区分に入るかで、メッシュの人口を丸ごと数えます）。想定（大きいほう・洪水・高潮）に従います。洪水と高潮は足し合わせません。
- 65歳以上が不明（秘匿）のメッシュは、65歳以上の合計から除きます（総人口には入れます）。除いた数（実データで 122 メッシュ、総人口 1,184 人）は、「数え方とデータの注意」（折りたたみ）の注記に出します。
- 標高 0m 未満の土地の人口は、メッシュの中心を含む標高のセルが 0m 未満のメッシュの人口です（標高がない水面のセルは数えません）。
- 中心が23区の外にあるメッシュ（21 個、4,083 人）は数えません。
- 「数え方とデータの注意」（23区全体では折りたたみ）にも、同じ数え方を書いています。クローズアップの円の中では、中心が円の中にあるメッシュについて、同じ数え方で数えます。
- 調査担当の別の数え方（メッシュの面積を浸水域で按分する）では、標高 0m 未満の土地に約95万人、高潮の浸水域に約356万人でした。この数え方（実データ）は、標高 0m 未満が 962,288 人（約 +1.3%）、高潮の浸水域（0.5m 未満を含む）が 3,522,364 人（約 -1.1%）で、桁が合い、差は約 1% です。メッシュの中心で判定するか、面積で按分するかの違いと、調査側の値が概数であることの範囲に収まる大きさなので、差の原因の調査はしていません。
- 画面の値は、`public/data/` のファイルを Node で直接読んで求め直した値と一致することを、`node scripts/verify-exposure.mjs` で確かめます（想定3通りの区分ごとの人口と65歳以上人口、標高 0m 未満の人口、避難場所の数）。

## 23区全体の集計の見せ方

何も選んでいないときの右の列です（`src/info/Overall.tsx`、文言と概数は `src/info/overallModel.ts`・`src/aggregate/wardExposure.ts` の `approxPeople`）。住民説明会の説明や報道の解説のように、スクリーンに映して、離れた席から読まれる場面を想定しています。

- **大きく見せる数字は4つ**（上から）
  1. **深さ 3m 以上の浸水が想定される区域に住む人**（約242万人、うち65歳以上 約56万人）：この地図の主題の数字。いちばん大きく出す。浸水が想定される区域全体（0.5m 未満を含む。約555万人）は、その下に小さく添える
  2. **標高 0m 未満の土地に住む人**（約96万人）：「海面より低い土地に、これだけの人が住んでいる」を、浸水の想定とは別に見せる。想定の切り替えによらない
  3. **洪水・高潮で使える避難場所**（672 か所）：想定の切り替えによらない
  4. **浸水が深いのに、洪水・高潮用の指定がない区**（2 区：江戸川区・足立区。区の人口の 75%・60% が深さ 3m 以上の区域に住む）：「避難できる場所はここにある（あるいは、近くにはない）」の「ない」の側。琥珀の枠で、見落とされないようにする。データ未公開の区と、浸水が小さく指定がない区は、その下に小さく2行で添える（地図の3通りの区に対応）
- **概数**：大きな数字は概数で、10 万人以上は万人単位に四捨五入します（2,415,153 人 → 約242万人。10 万人未満は、小数1桁の万人、1 万人未満は百の位）。正確な値は、マウスを置いたときの表示と、下の表にあります。
- **想定との対応**：「想定：洪水と高潮の大きいほう」を、大きな数字のすぐ上の橙の札に出し、1文で意味を添えます。「大きいほう」は、洪水と高潮を足し合わせたものではなく、地点ごとに深いほうの想定を採ったものです（洪水だけ・高潮だけのときは、その旨）。想定は、右上のパネルの「浸水」の行で切り替えます。大きな数字（深さ 3m 以上の人）と表は想定に従い、標高 0m 未満・避難場所の数・区の分類は想定によりません（区の分類は、洪水と高潮の大きいほうで固定）。
- **深さの区分ごとの表**：区分ごとの人口を、横棒（長さは、区分ごとの人口の最大に対する比。色は浸水の段の配色）で並べ、人口・割合・65歳以上を数字で添えます。該当のない区分（20m 以上、10〜20m は 0 人）は、棒にせず、「10〜20m・20m 以上：想定される区域に住む人なし（0 人）」の1行にまとめます。合計と標高 0m 未満の土地は、従来どおり表の下に出ます。
- **折りたたみ**：数え方（メッシュの中心で判定、按分なし、65歳以上が不明のメッシュ、数えなかったメッシュ）、避難場所の読み方（災害の種別ごとの指定、データが最新でない場合、「指定がない」≠「避難できない」、区の分け方）は、「数え方とデータの注意」のボタンで開きます（既定は閉じる。開閉は、カーソルを地図に置いて列が切り替わっても保たれます）。
- **常に見えるもの**：試作の注意（「試作です。避難の判断には使えません。…」）は列の最下部に固定し、操作の手がかりは、スクロールする集計の外（注意の上）に置きます。
- **文字の大きさ**：列の幅に合わせて拡縮します（CSS のコンテナ幅の単位）。最大の数字（約242万人）の文字の大きさは、列 560 px（2000×1100）で約 72 px、列 380 px（1400×1000・1000×700）で約 47 px。避難場所の数などのカードの数字は、それぞれ約 42 px・約 28 px。

## 避難場所の指定のない区（3通りの書き分け）

避難場所のデータ（国土地理院の指定緊急避難場所）では、洪水・高潮で使える場所が 0 件の区が、意味の違う3通りに分かれます。「0 件」を同じ書き方で並べると、「新宿区は危ない」とも「足立区は新宿区と同じ程度」とも読めてしまうので、書き分けます（`src/aggregate/wardExposure.ts` の `classifyWard`）。

| 種類 | 意味 | 判定 |
| --- | --- | --- |
| データ未公開（`unpublished`） | このデータに、指定緊急避難場所を公開していない。「ない」のではなく「データがない」 | `shelters.json` の `published` が false |
| 浸水が深いのに指定がない（`deep-none`） | 公開していて、洪水・高潮用が 0 件で、区の浸水の想定が深い | 洪水・高潮用が 0 件、かつ深さ 3m 以上の区域に住む人が区の人口の 10% 以上 |
| 浸水が小さく指定がない（`shallow-none`） | 公開していて、洪水・高潮用が 0 件で、区の浸水の想定が小さい。問題を示すものではない | 洪水・高潮用が 0 件、かつ深さ 3m 以上の区域に住む人が区の人口の 10% 未満 |
| （指定あり） | 洪水・高潮で使える避難場所がある | 印をつけない |

- **判定の基準**：区の人口のうち、**深さ 3m 以上（浸水深ランク 3 以上）の区域に住む人の割合が 10% 以上**（`DEEP_SHARE_THRESHOLD`）かどうか。区の名前は決め打ちにせず、データ（人口・浸水想定・避難場所）から、読み込み時に求めます。10% は、実データで、0 件の区の値が 0.7〜0.9%（新宿・文京）と 60〜75%（足立・江戸川）に大きく分かれる間に置いた、見やすい区切りです。10% は、洪水・高潮用が 0 件の区を分けるための基準で、区の危険度の一般的な基準ではありません（洪水・高潮用の指定がある区にも、荒川 66%・台東 54%・北 36%・板橋 20% など、10% を超える区があります。それらは「指定あり」として、印をつけません）。
- **数え方**：23区全体の集計（[集計の数え方](#集計の数え方浸水が想定される区域に住む人)）と同じ。メッシュの中心を含む区に、メッシュの人口を丸ごと数え、想定は洪水と高潮の大きいほうに固定します（画面の想定の切り替えで、区の分類が変わらないようにするため）。区の人口は、浸水想定の格子の内側に中心があるメッシュの合計です。

## データの再生成

`public/data/` のデータは、公開データを取得して `scripts/build-*.mjs` で作ります（`npm run` には登録していません。リポジトリのルートで `node scripts/build-boundary.mjs` のように直接実行します）。インターネットへの接続が必要です。

- ダウンロードしたデータは `.cache/` に保存し、同じ URL は2回目から取得しません（`.cache/` は Git に含めません）。
- 出力は何度実行しても同じです。コミット済みの `public/data/` を、下の順で作り直しても、差分は出ません（`git status` で確かめられます）。

### 実行の順番

**最初に区境界を作ります。** 区境界の輪郭は、ほかの前処理が「その地点が23区内か」の判定に使います。それ以外の順番は自由です。

```sh
node scripts/build-boundary.mjs       # 1. 区境界（最初）
node scripts/build-elevation.mjs      # 2. 以降は順不同
node scripts/build-population.mjs     #    250 m メッシュ（既定）。65歳以上人口も入る
node scripts/build-roads.mjs
node scripts/build-transit.mjs
node scripts/build-facilities.mjs
node scripts/build-flood.mjs           #    浸水想定。標高との突き合わせ（確認）を出すので、標高の後に実行する
node scripts/build-shelters.mjs       #    避難場所（区境界のあとに実行する）
node scripts/validate-data.mjs --require-all   # 3. 検証（全ファイルがそろっていることも求める）
```

避難場所は、国土地理院が区ごとに更新するため、取得し直すと件数が変わることがあります（この README の件数は 2026年10月19日の更新分）。人口の 65歳以上人口は、250 m メッシュの元データ（`tblT001142Q5339.txt`）の `T001142019`（500 m メッシュは `T001141019`）です。

人口だけ 500 m メッシュにするときは、`node scripts/build-population.mjs --size 500` を実行します。出力先は同じ `public/data/population.geojson` で、**上書き**されます（元データは別の統計表。メッシュ数は 250 m が 9,509、500 m が 2,382）。250 m に戻すには、オプションなしでもう一度実行します。

### 検証

```sh
node scripts/validate-data.mjs                   # public/data を、「データ仕様」の各項目に照らして検査する
node scripts/validate-data.mjs --require-all     # 全ファイルがそろっていることも求める
node scripts/validate-data.mjs public/data-fixture --require-all   # 仮データの検査
node scripts/build-elevation.mjs --check         # 標高を既知の地点と照合する
node scripts/build-flood.mjs --check             # 浸水想定を、既知の地点・標高と突き合わせる
```

避難場所と高齢者については、`shelters.geojson` の項目（真偽値、並び、座標が区の内側で、`ward` が座標から求めた区名と一致するか）、`shelters.json`（区のコードの昇順、`published` と件数の関係、`shelters.geojson` を数え直した件数との一致、区境界の区と一致するか）、`population.geojson` の `elderly`（`null` か 0 以上の整数で、総人口以下）と `elderlyMerged`（真偽値）も検査します。

違反があると終了コード 1 で終わります（引数やディレクトリの誤りは 2）。ファイルが未作成のものは「未作成」と表示します。

浸水想定（`flood.json` と `flood-*.bin`）は、ファイルのバイト数、値の範囲（浸水深 0〜6、継続時間 0〜7、255 = 区の外）、`flood.json` の範囲とランクの表と出典を検査します。`boundary.geojson` があれば、セルの中心が区の外のセルが 255 であること、区内のセルが 255 でないことも検査します。高潮の継続時間（`flood-tide-duration.bin`）は最大 5、洪水の継続時間は最大 7 です。`flood.json` の `files` が実際のファイル名と一致していることも検査します。仮データ（`public/data-fixture/`）の浸水想定は、`scripts/lib/flood-fixture.mjs` の `generateFloodFixture` が、仮データの標高と区から作った、検査を通る仮のもの（`node scripts/make-fixtures.mjs` が書き出します。実在の浸水想定ではありません）です。

## スクリーンショット

画面の確認用に、Playwright（Chromium）で撮影するスクリプトが2つあります。どちらも Vite を自動で起動し（空いているポートを使います）、終わると止めます。`shots/` は Git に含めません。

### 1枚を撮る：`scripts/shot.mjs`

```sh
node scripts/shot.mjs --query "data=fixture&spacing=5000" --out shots/stack.png
node scripts/shot.mjs --out shots/now.png --require-ready    # 実データで、読み込みの成否も確かめる
```

ブラウザで開き、`window.__ready` が true になる（最大 30 秒）まで待って、画像に保存します。実行の最後に、保存先、ページを開いてから撮影直前までの所要時間、ブラウザのコンソールエラーの一覧を表示します。

| オプション | 意味 |
| --- | --- |
| `--query <q>` | URL クエリ（[URL クエリ](#url-クエリ)） |
| `--out <path>` | 出力パス（既定 `shots/shot.png`） |
| `--size <幅x高さ>` | ビューポート（既定 `1400x1000`） |
| `--scale <n>` | deviceScaleFactor（既定 1。人が見る画像は 2 にする） |
| `--hover <x,y>` | 撮影前にマウスを動かす画面座標。探針の確認に使う |
| `--wait <ms>` | 撮影前の追加待ち時間 |
| `--url <URL>` | 起動済みのサーバーを撮る（Vite は起動しない。`--query` は URL に付け足す） |
| `--require-ready` | 撮影前に、区境界と5レイヤーの読み込み状態（`window.__store` の `status`）がすべて `ready` か確かめる。`ready` でないものがあれば、その名前を表示し、画像は保存したうえで終了コード 1 で終わる |

`--require-ready` を付けない場合、読み込みに失敗したレイヤーがあっても、終了コードは 0 です（失敗は画面の「読み込み失敗」と、コンソールエラーの一覧に出ます）。

- 画像は `<出力先>/<シナリオ名>.png`（例：`01-default.png`）。あわせて `index.md` に、シナリオごとの読み込み状態（区境界と5レイヤーがすべて `ready` か）、コンソールエラーの件数、所要時間をまとめます。

| `--out <dir>` | 出力先（既定 `shots/final`） |
| `--data fixture` | 全シナリオに `data=fixture` を足す（仮データで撮る） |

### 配置と操作を確かめる：`scripts/verify-layout.mjs`、`scripts/verify-section.mjs`、`scripts/verify-align.mjs`

```sh
node scripts/verify-layout.mjs                 # 実データ。全体の地図の大きさと位置、右の列の中身、探針・クローズアップ・断面の配置
node scripts/verify-section.mjs                # 仮データ。「断面」の操作（線を引く・動かす・連動・Esc・「地点」との往復）
node scripts/verify-exposure.mjs               # 実データ。23区全体の集計を、public/data/ のファイルを直接読んで求め直し、画面の値（想定3通り。表と、大きく見せる概数）と照合する
node scripts/verify-wards.mjs                  # 実データ。区ごとの浸水が想定される区域・深さ 3m 以上の割合と、洪水・高潮用が 0 件の区の分類を、public/data/ を直接読んで求め直し、画面の値と照合する
node scripts/verify-align.mjs                  # 仮データ（--real で実データ）。右のグラフと全体の地図の段の対応：高さの一致、間隔の変化での追従と縦並びへの切り替え、並べ替え、カーソルでの連動
```

いずれも Vite を自動で起動し、1つでも外れた項目があれば内容を表示して終了コード 1 で終わります（`--url` で起動済みのサーバーを使えます）。`verify-layout.mjs` は、探針の固定前後、断面の有無やモードの切り替えで、全体の地図の `zoom` と `target`（大きさと位置）が変わらないことを、1400×1000・2000×1100・1000×700 で確かめます。`verify-section.mjs` は、全体の地図の水色の印の位置を、画面の画素の色で、右のグラフのカーソルの位置と突き合わせます。`verify-align.mjs` は、各グラフの枠の縦の中心と、各段の平面の中心の、画面上の y のずれ（2000×1100・1400×1000。4 px 以内）、間隔を 12 → 20 → 3 → 0 km と動かしたときの追従と縦並びへの切り替えが1回だけであること、ゆっくり 12 → 0 → 12 km と往復しても切り替えが行きと帰りに1回ずつであること、並べ替えでグラフの順番が変わること、グラフにカーソルを置くと対応する段以外が暗くなり（画素の明るさで測る）外すと戻ることを確かめます。

### 1フレームの描画時間を測る：`scripts/measure-frame.mjs`

```sh
node scripts/measure-frame.mjs                          # 5枚すべてと、1枚ずつ（ほかの段は hidden）、1枚も出さない場合
node scripts/measure-frame.mjs --only all,roads --frames 8 --extra "rx=90&zoom=-3"
```

Vite を自動で起動し、`window.__ready` と数秒の待ちのあと、`requestAnimationFrame` のたびに視点を1度ずつ回して描き直させ、フレームの間隔（ms）を測ります。表に、構成ごとの中央値と各フレームの値を出します。GPU のない環境では描画（WebGL）が時間のほぼすべてなので、描く量を変えたときの比較に使います。

| オプション | 意味 |
| --- | --- |
| `--frames <n>` | 1構成あたりのフレーム数（既定 5） |
| `--only <a,b>` | 測る構成（`all` / `none` / レイヤーID をカンマ区切り）。既定は全部 |
| `--extra <q>` | 全構成の URL に付け足すクエリ |
| `--size <幅x高さ>` / `--url <URL>` | `shot.mjs` と同じ |

描画の負荷は、線の頂点数にほぼ比例します（端や継ぎ目の丸めの有無では変わりません）。区の境界線は表示中の段ごとに1組描くので、5枚の積層では最も重くなります。そのため、描画に使う線（区の境界線、鉄道）は、読み込み時に許容誤差 3 m で間引いて（`src/layers/simplify.ts`）います。探針の参照（区名、路線）は元の形のデータのままです。

## 出典表示の部品

画面の右下には、出典の1行が常に出ています（`src/App.tsx` が `src/panel/Credits.tsx` を置いています）。

- 1行：「出典：国土数値情報（国土交通省）、国土地理院、e-Stat（総務省統計局）、東京都港湾局のデータを加工して作成　詳細 ▴」。狭い窓では、文の末尾を省略して1行のまま表示します。
- 押す（または Enter / スペース）と、「データの出典」の詳細が上に開きます。各データの出典と配布元へのリンク、基準時点、利用上の注意（浸水想定は想定最大規模で、洪水は支川の氾濫・高潮・内水を含まないこと、避難場所は災害の種別ごとの指定で、最新でない場合や未掲載の場合があることなど）、利用規約へのリンクが載ります。詳細は、右上のパネルなどの上に重なって開き、中が長いときは詳細の中をスクロールします。
- 閉じるには、「閉じる」ボタン、1行の部分をもう一度押す、Esc（出典表示にフォーカスがあるとき）。

配置は、右上のパネル、右の列の表、積層（と各段のレイヤー名）のいずれとも重ならないように決めています。

- 右下の隅に置き、画面の下端から 3 px（積層の下の余白 24 px の内側に収まる）。右端は右上のパネルとそろえて 12 px
- 右上のパネルは、1行の高さのぶんだけ下端を空けて収めます（画面が低いときは、パネルの中をスクロールする）
- 幅は、最大 640 px、かつ画面の幅から左右の余白を引いた幅まで。1000 px 幅でも、1行がすべて見えます。右の列は、下端をこの1行のぶん空けています

部品として使うには、位置を呼び出し側が決めます。

```tsx
import Credits from './panel/Credits';

<Credits style={{ position: 'absolute', right: 12, bottom: 3, zIndex: 10 }} />
```

- `style` / `className`：位置と大きさの指定。部品自身は位置を決めない。ほかの部品の上に詳細を重ねるため、`zIndex` を付ける
- `opens`：詳細を開く向き。`'up'`（既定、画面の下端に置くとき）か `'down'`（上端に置くとき）
- 出典の文面、リンク、基準時点は `Credits.tsx` の `ENTRIES` にあります。データを足したり変えたりしたら、[出典](#出典)の表と合わせて直してください
